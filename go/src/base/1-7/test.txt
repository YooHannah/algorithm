# Go语言并发编程：协程（Goroutine）专题培训教案

## 一、 培训目标
1.  **理解本质**：搞懂协程（Goroutine）与操作系统线程（Thread）的区别。
2.  **掌握语法**：熟练使用 `go` 关键字启动协程。
3.  **掌握同步**：理解 `sync.WaitGroup` 和 `channel` 的配合使用（重点）。
4.  **规避陷阱**：深刻理解并发安全问题（数据竞争）及 `context` 的使用。

## 二、 培训大纲与讲稿要点

### 模块1：为什么需要协程？（破冰与引入，5分钟）
*   **痛点引入**：传统的多线程并发模型（如 Java/C++）有什么问题？（答案：线程太重，上下文切换开销大，占用内存多，通常一个线程占 1MB 栈内存）。
*   **Go 的解法**：Goroutine（协程）。
    *   **极轻量**：初始栈仅 2KB，可动态扩容。
    *   **切换快**：由 Go 运行时（Runtime）调度，而非操作系统内核调度，属于用户态调度。
    *   **口号**：不要通过共享内存来通信，而要通过通信来共享内存。

### 模块2：协程基础语法（对应讲义基础，10分钟）
*   **启动方式**：只需在函数调用前加 `go` 关键字。
    ```go
    go myFunction() // 启动一个新协程执行 myFunction
    ```
*   **核心特性**：
    *   主协程（main 函数）退出，所有子协程强制结束（不管有没有执行完）。
    *   子协程的执行顺序是不确定的。
*   **代码演示（反例）**：
    *   写一个 `for` 循环启动 10 个协程打印数字，主协程不等待。演示什么都不会打印，或者只打印部分（因为主协程直接退出了）。
    *   **引出问题**：如何让主协程等待子协程执行完毕？

### 模块3：协程同步机制（核心难点，15分钟）
*   **方案一：`sync.WaitGroup`（等待组）**
    *   **适用场景**：主协程等待一批子协程全部完成任务（不需要获取子协程的返回值）。
    *   **三个核心方法**：
        *   `Add(delta int)`：计数器增加（通常在启动协程前调用）。
        *   `Done()`：计数器减 1（通常在协程内部用 `defer wg.Done()` 调用）。
        *   `Wait()`：阻塞主协程，直到计数器归零。
*   **方案二：`channel`（通道）**
    *   **适用场景**：协程之间需要传递数据（通信），或者需要等待单个/特定协程的返回结果。
    *   **分类**：无缓冲通道（同步阻塞）、有缓冲通道（异步）。
    *   **经典用法**：用通道实现“生产者-消费者”模型。

### 模块4：并发安全与锁（避坑指南，15分钟）
*   **引出问题**：多个协程同时读写同一个变量会发生什么？
    *   *案例*：1000 个协程同时对同一个全局变量 `count++`。最终结果大概率小于 1000。
    *   *原因*：`count++` 不是原子操作（包含读取、计算、写入三步），发生**数据竞争（Data Race）**。
*   **解决方案：`sync.Mutex`（互斥锁）**
    *   在读写共享资源前 `mu.Lock()`，操作完后 `mu.Unlock()`。
    *   **最佳实践**：习惯性使用 `defer mu.Unlock()`，防止死锁或忘记解锁。
*   **解决方案：`sync.RWMutex`（读写锁）**
    *   适用于读多写少的场景。允许多个协程同时读，但写的时候必须互斥。
*   **检测工具**：介绍如何使用 `go run -race main.go` 来检测代码中的并发安全问题。

### 模块5：协程的生命周期控制（进阶必学，15分钟）
*   **痛点**：如何优雅地通知子协程停止工作？（比如 HTTP 请求超时，需要取消后台的所有数据库查询协程）。
*   **核心工具：`context` 包**
    *   `context.Background()`：根 Context。
    *   `context.WithCancel(parent)`：创建可取消的 Context，手动调用 `cancel()`。
    *   `context.WithTimeout(parent, time.Second*3)`：创建带超时的 Context。
*   **代码演示**：主协程创建一个 3 秒超时的 Context，子协程监听 `ctx.Done()`，超时后子协程自动退出。

## 三、 课堂互动与练习（10分钟）

**随堂测验（口头或选择题）：**
1.  如果一个程序只有主协程（main 函数），不加 `go` 关键字，它是并发执行的吗？（答案：不是，是顺序执行）。
2.  无缓冲的 channel（`make(chan int)`）发送数据和接收数据是阻塞的吗？（答案：是，必须收发双方同时准备好才能完成传递）。
3.  如果我用 `go` 启动了一个协程，但主协程没有等它，会报错吗？（答案：不会报错，但子协程会随主协程退出而被强制杀死）。

**课后作业：**
*   使用 `sync.WaitGroup` 编写程序：启动 5 个协程，每个协程计算一个数字的平方，并打印结果，主协程等待所有协程打印完毕后再退出。
*   使用 `channel` 实现：一个协程生产 1-100 的数字，另一个协程消费这些数字并打印，使用 `range` 遍历 channel。
